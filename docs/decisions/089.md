# 89. An IPA for the player's own certificate, signed on the iPhone

2026-11-13

Each release from the version of November 15 publishes a second IPA beside Cartouche's, `Cartouche-<version>-Own-Certificate.ipa`, for a signing app on the iPhone ([imported-signing.md](../imported-signing.md#install-with-no-computer)): the release's IPA with `CartoucheImportedSigning` set in its `Info.plist` and no app extension ([`own_certificate_ipa.py`](../../app/scripts/own_certificate_ipa.py)), checked by the same publish guard, and listed in the source beside the IPA in three fields that only Cartouche reads (`ownCertificateDownloadURL`, `ownCertificateSize`, `ownCertificateSHA256`). Without the Cartouche Installer's `CartoucheSigningHandoffKey`, Cartouche knows that a signing app signed it on the iPhone: its setup, and its first game's guide, where the certificate's step takes the place of LocalDevVPN's and the Apple ID's, ask for the certificate and its password alone, never a profile, since Cartouche signs the games with its own (`embedded.mobileprovision`), which must list that certificate. **System → Setup** says what its signature lacks of what that profile allows, from the entitlements Cartouche runs with ([`CartoucheOwnSignature.swift`](../../launcher/Sources/CartoucheOwnSignature.swift)): Increased Memory Limit, and the games' keychain groups. A new version is the new IPA to download, only from Cartouche's releases on GitHub, which the player signs again; Cartouche never installs it. The Cartouche Installer takes this IPA with the player's own certificate, and refuses it with an Apple ID. The site gets no button for it, and the docs name no seller of certificates nor signing app, until a player has installed it with a real certificate. Measured as `signing` `iphone` on `app.opened`, with `iml` and `gameKeychains`. Amends 79 ([decisions.md](../decisions.md)).

**Why.** Ad chose it among the works of 2026-11-13, from the roadmap (79). A signing app signs the IPA it is given with the player's certificate and profile, but takes no extension out of it and does not set Cartouche's mode: the IPA must come ready. The profile that 79 had Cartouche ask for is the one the signing app put in Cartouche, which Cartouche reads itself: asking for it again was one more file to find, and a wrong one to give. Without Increased Memory Limit, iOS gives about 3 GB, too little for most games. Signing apps often copy the profile's keychain groups into the signature as written, `<team>.*`, which names none of the games' groups: most games use none, so Cartouche only says so. Signed with an Apple ID, this IPA would start asking for a certificate, without the Apple ID's setup. The source's readers, the Installer and the copies of Cartouche from 0.10, ignore the fields they do not know, as their tests now show. No real certificate has been tried, which is why the site waits.
