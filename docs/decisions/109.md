# 109. A new decision is a file of its own

2026-11-14

A new decision is a file of its own in `docs/decisions/`, named by its number on three digits, rather than a row at the end of [decisions.md](../decisions.md), whose table keeps the decisions it has ([README](README.md)). A pull request whose decision is still a row there moves it to its file the next time it takes main in.

**Why.** Since 2026-11-14, a pull request is merged as soon as its checks pass and GitHub finds no conflict with main, without waiting for its turn: asked for that day, after twelve hours or more of waiting to merge into main. Every pull request added its decision as a row at the end of the table, so each merge put the other open ones in conflict there: at 15:25 UTC, 8 of the 14 open pull requests conflicted with main, all of them in decisions.md, and each had to take main in and run its checks again, on GitHub's Macs, where a job then waited an hour and a half. Files of their own never meet.
