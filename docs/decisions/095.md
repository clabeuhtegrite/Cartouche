# 95. Cartouche comes to the Mac in Cartouche Builder

2026-11-13

Cartouche comes to the Mac in Cartouche Builder, which builds each game for the Mac, plays it there and shows it in Cartouche's console. The builder builds each game for the iPhone and for the Mac it runs on, unless the player turns one of the two off: its IPA, then, in the same batch and from the same nxnative commit and files, its app for that Mac (nxnative's `--platform mac-app`), kept in the games folder beside its IPA, the player's library: as it is on the Mac's own disk, played from there; in one file on a NAS (or a disk that cannot hold an app), installed on the Mac the first time the game is played there, in the Applications folder of the player's session or in a folder they chose, and made again of each new build while it is there ([`macapps.py`](../../builder/cartouche_builder/macapps.py), [builder/README.md](../../builder/README.md#your-games-on-this-mac)); `builder.macInstalled` counts those installs. Either can be turned off for every game in the settings, or for one game on its sheet, never both: a game built for neither is a game no longer followed. A Mac app never takes the place of an app that is not the game's, never replaces one while the game runs, and never lands half built: it is put together beside the old one, hidden, and swapped in. One that fails leaves the IPA built and waits for nxnative or the game's files to change; once the IPA is up to date, a Mac app missing or older than it is built alone. On the disk of the build folders, the app keeps the room of the extracted files it was cloned from once they are removed, so it waits for the next batch, as a build does, when less than the free room the settings keep would be left there. The telemetry counts the Mac apps apart (`builder.macBuilt`, `builder.macFailed`, `builder.macSkipped`), so that `builder.built` stays an IPA's for nxnative's page ([decision 82](../decisions.md)). A game built for the Mac is played from the builder, started as the Finder starts it, through LaunchServices, straight into the game or with nxnative's settings window first, and followed until it ends, wherever it was started; its saves are kept in step with the iPhone's copies in the saves folder with Cartouche's own decisions (`CartoucheSaveSync`), the newest copy coming before a game the builder starts and the Mac's saves going after every game, and Cartouche on the iPhone finds a game's folder of copies by its title ID, whatever name the Mac gave it ([`MacSaves.swift`](../../builder/mac/Sources/BuilderKit/MacSaves.swift)); `builder.played` and `builder.saves` count how games end and what their saves did, never a name or a path. Cartouche's console, the iPhone's own screens, is built for the Mac from the launcher's files, the iPhone's code as it is but for its parts marked `#if os(iOS)` ([`CartoucheConsole`](../../builder/mac/Sources/CartoucheConsole)), a game being the app nxnative built for the Mac; the app's gallery shows it, and the window is to show it beside the builder, the player switching between the two. It is tested against a fake nxnative that lays its apps out as nxnative's packer does, whose games play; no Mac app has been built, nor a game played, with it on a real Mac yet.

**Why.** Ad chose to play the games on the Mac too, with a controller and the saves in step with the iPhone, and asked for both by default, each one able to be turned off (2026-11-13). nxnative makes a double-clickable Mac app of a game from the build it makes the IPA from, and on the same APFS disk the app's game files are clones of the build's, which take no room while those are kept. The IPA stays the reference and goes first: a Mac app that does not build never holds the iPhone's back, and one made of another commit than the IPA is built again. Ad then asked for the whole of Cartouche on the Mac, not a Play button alone, and for the console and the builder in one app with a switch between them, the builder to be renamed Cartouche with a release (2026-11-13). The console's screens are the launcher's own files, linked rather than copied, so that the Mac shows what the iPhone shows and a change to one is a change to both, which the Builder's workflow checks by building the Mac app again; what only the iPhone has, its memory limits, its signature, LiveContainer, is stood in for on the Mac, or left out.
