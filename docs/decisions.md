# Decisions

Choices that shape the project, with their reasons. A new decision gets a new entry; a reversed one is marked as such rather than deleted.

| # | Date | Decision | Why |
| --- | --- | --- | --- |
| 1 | 2026-11-05 | The project never hosts, downloads or lists downloadable games, keys or firmware. Players import their own. | Legal: only players' own copies are lawful to use. The update server and its tools enforce it ([LEGAL.md](../LEGAL.md)). |
| 2 | 2026-11-05 | The app is a fork of LiveContainer with SideStore built in, under AGPL-3.0. | One standalone app that handles signing, installing and renewal in the background. A guest app inside an existing LiveContainer would be smaller but not standalone. |
| 3 | 2026-11-05 | Free Apple accounts only. | No player should need a paid developer account. Consequences: seven-day signatures, three apps, ten App IDs a week, and the memory capability requested through the developer services API. |
| 4 | 2026-11-05 | Fix SideStore so that it enables Increased Memory Limit, as GetMoreRam and AltStore 2.3 do, instead of shipping a separate tool. | The bigger games need about 6 GiB; one app must do it all. |
| 5 | 2026-11-05 | No StikDebug, no JIT. | nxnative runs games natively and needs no JIT. |
| 6 | 2026-11-05 | v1 plays games built on a Mac; v2 builds them on the iPhone. | v1 ships in a week on what already works; v2 needs the spikes S2 to S4. |
| 7 | 2026-11-05 | v2 accepts Switch games as NSP with the player's own `prod.keys`, and Switch 2 games as nxnative takes them. | The same inputs as nxnative's own script. Keys stay on the phone. |
| 8 | 2026-11-05 | Updates come from a Cloudflare R2 bucket, as a signed manifest of content-addressed chunks, and install automatically. Narrowed by 14: not Cartouche's own versions. | R2 has no egress fees; signing protects players if the bucket is ever tampered with; chunks keep updates small. |
| 9 | 2026-11-05 | Telemetry is opt-in. | Players decide what leaves their phone. |
| 10 | 2026-11-05 | Console-style interface. | A launcher for games, not a file manager. |
| 11 | 2026-11-05 | The repository is written in English. | Open source contributors and upstream projects work in English. |
| 12 | 2026-11-05 | The launcher's home screen is a catalogue of every supported game, the player's own first and featured; the others offer only "Import my copy". A game the player does not have gets a tile we design, not official cover art. | Players see at a glance what Cartouche can run on their iPhone. Cover art is not ours to redistribute; the icon of the player's own copy replaces the tile once imported. |
| 13 | 2026-11-05 | The interface follows the space it is given, never the iPhone model: one column on an iPhone or a folded iPhone Duo, the catalogue and a game's sheet together on an unfolded Duo or an iPad (narrowed by 19), nothing in the fold or under a camera. Duo layouts for games are proposed to nxnative, which draws them. | Apple's guidance for the Duo (size classes, system containers and bars, reserved regions) also covers every other iPhone and the iPad, so one design serves them all ([launcher/README.md](../launcher/README.md#every-iphone-the-iphone-duo-included)). |
| 14 | 2026-11-06 | Cartouche's own versions are published as GitHub releases of this repository, pre-releases while 0.x, and listed in the source of the built-in SideStore. R2 keeps the engine hosts, tools, pipeline lists and game sheets. | The built-in SideStore installs only a whole IPA from a direct link, not a manifest of chunks, and its source is already in this repository. Each release keeps its IPA next to its source code ([app/releases/README.md](../app/releases/README.md)). |
| 15 | 2026-11-06 | Cartouche keeps LiveContainer+SideStore's app group and keychain groups, and SideStore's bundle identifier for the built-in SideStore; its own bundle identifier, name, URL schemes and source stay. It takes the place of a LiveContainer+SideStore on the iPhone. | iloader gives its certificate only to an app it takes for a LiveContainer+SideStore, with exactly those groups. With names of its own, Cartouche 0.1.0 had no certificate, so it could neither sign a game nor renew itself, and the player wants one app that handles certificates and pairing by itself ([app/README.md](../app/README.md#identity)). |
| 16 | 2026-11-06 | Cartouche's Info.plist keeps the display name LiveContainer, and every localization of the app names it Cartouche. The setup needs no setting: SideStore signs in through the SideStore (New) anisette server, and its onboarding goes from LocalDevVPN to the Apple ID by itself, then back to Cartouche. | iloader places the pairing file only in the apps it knows by the display name of their Info.plist, and the player wants iloader's *Place In All Apps* rather than an export. The home screen, Settings, Files and the built-in SideStore show the localized name. The player wants the install fully automatic, with as few taps as possible, and every version is tested from a fresh install ([architecture.md](architecture.md#first-install)). The first reason did not hold: see 17. |
| 17 | 2026-11-06 | The pairing file comes from iloader's *Export*: Cartouche takes a pairing file the player drops on it from the computer, in Apple Devices, iTunes or the Finder, with no tap on the iPhone. The Info.plist keeps the display name LiveContainer. | iloader compares its list with the display name the iPhone reports, which is the localized one, so *Place In All Apps* does not list Cartouche (tested with 0.1.2 and iloader 2.4.1). The name LiveContainer still serves an iPhone in a language Cartouche has no localization for. Adding Cartouche to iloader's list is iloader's call. The Cartouche Installer puts the file in Cartouche itself since 25. |
| 18 | 2026-11-06 | main takes changes only through pull requests, squashed once CI has passed, with no exception for admins or workflows. The Release workflow publishes the GitHub release, then proposes the source entry in a pull request from `release/v<version>`. Workflows get read-only tokens, pin their actions to commits and pass a workflow audit. | Asked for on 2026-11-06: no more pushes to main. The release was the only thing that pushed to main, with a token any of its steps could use; a source entry now goes through the same checks as code. The rules live in `.github/rulesets` and are imported by an admin. |
| 19 | 2026-11-06 | The launcher is a console's home: the player's games and the games nxnative plays on the iPhone on two shelves of cartridges we draw, the game in focus under them, a dock, and every game of nxnative's list one step away, all driven by touch or a game controller. A game's sheet opens over the home, as a card on an unfolded Duo or an iPad, until iOS 27.1's `ArrangementView` can place them around the fold. | The player found 0.1's catalogue of lists plain and not made for the Duo, and wants every nxnative game in it. Cartridges carry the player's own icon or art we design, never cover art (12). The list comes from nxnative's profiles at the pinned commit ([catalog/README.md](../catalog/README.md)), so it follows nxnative. |
| 20 | 2026-11-06 | Cartouche is built with Xcode 27.2 and the iOS 27.2 SDK, on GitHub's `xcode-27` runners, and its gallery runs on the iPhone Duo simulator. | On an iPhone Duo, iOS gives the whole display only to an app built with Xcode 27 or later: built with Xcode 26.4, Cartouche 0.1 showed beside a black band that held the status bar. The SDK 27.2 is the minimum asked for the Duo, and the runners carry an iOS 27.2 runtime made for it (iPhone19,4). |
| 21 | 2026-11-06 | Cartouche installs, starts and uninstalls a game itself, with the steps LiveContainer's Apps tab takes and none of its questions, and shows a game's nxnative settings on a page of its own. Play writes `DM_LAUNCHER=0` into the game's `Documents/env.txt`, so the game starts at once; that page saves each choice where nxnative keeps it, in the game's preferences, through cfprefsd. | The player landed in the Apps tab after an install and on nxnative's settings screen at each start, had no way to uninstall a game, and asked for nxnative's settings in Cartouche, cleanly (2026-11-06). Without its screen, nxnative applies the saved choices (`LauncherSettings.swift`, `applySaved`), and cfprefsd is what both the game and Cartouche read through, so neither sees a stale copy ([launcher/README.md](../launcher/README.md#what-the-first-build-does)). |
| 22 | 2026-11-06 | A game's cartridge shows its official cover and its sheet its official artwork, from IGDB (Twitch's game database): the catalogue keeps only IGDB's IDs (`catalog/covers.json`, written by `catalog/tools/igdb_covers.py`), and each iPhone loads the images from IGDB's image server and keeps them in its caches. Cartouche draws its own label for a game IGDB has no cover for, and until the image has loaded. This replaces "never cover art" in 12 and 19. Since 0.3.0, every cartridge shows its cover whole, the player's own games included, on a label shaped like a game case. | The player asked for the games' official covers, loaded online (2026-11-06). Neither the repository nor the app carries an image; the IGDB credentials the tool needs are repository secrets, used by the Covers workflow only. The player found the covers cut off (2026-11-06). |
| 23 | 2026-11-06 | Cartouche keeps the player's games and saves on storage of their own: a shared folder of their Mac, PC or NAS over SMB 2 or 3, through SMBClient, or a folder the Files app reaches; S3, FTP and SFTP follow, a release each. The player signs in with their own account, and each password stays in the iPhone's keychain. The library lists the games of the games folder, installs one from there and copies an installed one back as an IPA; each game's saves are copied after each game, the ten newest kept. There is no address to paste, no link to follow and no public bucket. | The player asked for their games and saves on their own storage, the games they have not installed in the library, and connectors inside the app, since the Files app is unreliable and impractical for this (2026-11-06). Only the player's own places, with their own account, keep 1 true: Cartouche never becomes a way to download games. Google Drive would need an OAuth app of ours, so it is left out. SMBClient (MIT) was approved by the player; it is pinned in `app/SMBClient` and linked by a patch ([NOTICE.md](../NOTICE.md)). |
| 24 | 2026-11-06 | Cartouche shows none of LiveContainer's or SideStore's pages: no tab bar, no **Open SideStore** button, no page in the Settings app and no share sheet extension. The console fills the window and the System page opens over it; a link opened with Cartouche goes to Cartouche or nowhere. Cartouche drives both apps without showing them. Until it signs the player in on a screen of its own (27), its setup still opens the built-in SideStore's onboarding for the Apple ID. | The player wants the apps Cartouche is built from invisible, driven from Cartouche and never entered (2026-11-06). LiveContainer's Apps and Settings tabs were its own pages, and **Open SideStore** led into SideStore's ([app/patches/README.md](../app/patches/README.md)). |
| 25 | 2026-11-06 | Cartouche has an installer of its own for macOS and Windows, the Cartouche Installer ([`installer/`](../installer/README.md)): a fork of iloader, under iloader's MIT licence. It downloads the latest Cartouche from its release and checks it against Cartouche's source, installs it with Increased Memory Limit and the certificate through isideload, as iloader does, and puts the pairing file in Cartouche itself. Each version is the release `installer-v<version>`, published without GitHub's *Latest* mark. Cartouche's words point to it instead of iloader. | iloader places a pairing file only in the apps of its own list, and its maintainers closed the pull request that added Cartouche to it ([nab138/iloader#1116](https://github.com/nab138/iloader/pull/1116)), so the player had to export the file and drop it on Cartouche. The player wants the install fully automatic, and asked for an installer of our own copied from iloader. A fork keeps what iloader does well, the account, the certificate and the memory capability, with no dependency iloader does not have. A pairing file exported from iloader still works. |
| 26 | 2026-11-06 | Cartouche offers its own updates, and the built-in SideStore installs them without being shown: Cartouche reads its source when it opens and when it comes back, offers a higher version over the console and on the System page, and runs SideStore's *Update Cartouche* action in LiveProcess, as it does to renew itself ([`app/patches/sidestore/0010`](../app/patches/README.md), [launcher/README.md](../launcher/README.md)). When SideStore starts the install, Cartouche leaves the screen by itself, for iOS to replace it. | With SideStore out of sight (24), its My Apps page, which offered Cartouche's updates, is out of reach: the player could no longer update Cartouche without a computer, and asked for an update prompt that keeps the built-in SideStore (2026-11-06). |
| 27 | 2026-11-06 | The player signs in with their Apple ID on Cartouche's own screen, and types the verification code Apple sends there too. The built-in SideStore signs in with it without being shown, through its *Sign In to Cartouche* action in LiveProcess, as it renews Cartouche ([`app/patches/sidestore/0011`](../app/patches/README.md), [launcher/README.md](../launcher/README.md#setup)). Cartouche leaves the Apple ID and password in the keychain it shares with SideStore, which reads them once and keeps them in its own items, as after any sign-in; the verification code goes through the same keychain. What SideStore's screens would ask is decided as the onboarding would have it, and an error ends the sign-in, for Cartouche to show. Cartouche counts as set up once SideStore is signed in. When iOS refuses what LiveContainer signs with the certificate SideStore handed over, as after an install from another computer that revoked it, Cartouche has SideStore sign in again by itself with the Apple ID it keeps, and offers no update until the certificate works (0.5.1). | The player wants SideStore invisible, driven from Cartouche and never entered (24, 2026-11-06); its onboarding was the last of its pages Cartouche opened. Without a sign-in, SideStore can neither renew Cartouche nor install its updates. |
