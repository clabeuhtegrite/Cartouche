# Catalog

What the launcher knows about games and devices. These files are published as `catalog` artifacts: every game sheet is an entry in the launcher's catalogue, and its details fill the game's sheet.

- [`games/<title ID>.json`](games/): one sheet per supported game: what it needs (iOS version, GPU features, the memory capability, its measured memory peak), recommended settings, and results measured on real devices. Schema: [`schema/game.schema.json`](schema/game.schema.json).
- [`devices.json`](devices.json): memory limits measured on real devices, with and without Increased Memory Limit. Schema: [`schema/devices.schema.json`](schema/devices.schema.json). A tester's iPhone joins it from the report they send from Cartouche's System › Report a problem, which ends with the iPhone's entry, its memory limit measured as the schema says: [`tools/add_device.py`](tools/add_device.py) reads the report, as it was sent or as the GitHub issue it became, and adds the model, or a measurement of a model the file has. For a new model it needs the chip, from the model's Apple specifications, since iOS does not say it: `catalog/tools/add_device.py REPORT --chip "A19 Pro"`.
- [`nxnative.json`](nxnative.json): every game nxnative has a profile for, at the commit Cartouche pins ([`nxnative.commit`](nxnative.commit)): title ID, name, Switch or Switch 2, genre, where nxnative plays it (iPhone, Mac, bring-up, or not said), as the opening paragraphs of the game's notes (`dm/games/<title ID>/README.md`) say it, else its profile's opening comment, which is often older, and the engine, game version and SDK of its profile, with the other regions' title IDs. The launcher lists all of them, the player's own first. [`tools/nxnative_games.py`](tools/nxnative_games.py) writes it from nxnative's `dm/games/`, and CI checks that it still matches. Schema: [`schema/nxnative.schema.json`](schema/nxnative.schema.json).
- [`covers.json`](covers.json): each game's official cover and artwork on [IGDB](https://www.igdb.com), Twitch's game database, as IGDB's game and image IDs, never an address, and its genre there, as one of the launcher's genres, which the launcher shows for a game whose nxnative profile says none: the launcher builds the images' addresses on `images.igdb.com` itself and loads them on the player's iPhone, and draws its own label for a game IGDB has no cover for. [`tools/igdb_covers.py`](tools/igdb_covers.py) finds each game by name among IGDB's Nintendo Switch and Nintendo Switch 2 games, with a Twitch application's credentials; the Covers workflow runs it with the repository's secrets `IGDB_CLIENT_ID` and `IGDB_CLIENT_SECRET` when `nxnative.json` changes, and keeps the file it wrote on the branch `catalog-covers/<branch>`, to commit with the change. Every day, the [Live covers](../.github/workflows/live-covers.yml) workflow runs it on the games of `nxnative.json` and of nxnative's main branch, checks what it wrote with the publish guard and the schema, and keeps it on the branch `live-covers`, which the launcher reads over the list it carries: a game nxnative adds after a version of Cartouche, and a game IGDB had no cover for yet, get their covers without a new version. A game it matches wrongly, or not at all, is pinned to its IGDB entry in the tool's `MATCHES`, and a game whose genre on IGDB is not the one players know it by, to its genre in `GENRE_PINS`. Schema: [`schema/covers.schema.json`](schema/covers.schema.json).

The app carries these files as they are when it is built, in `CartoucheCatalog/` ([launcher/README.md](../launcher/README.md#what-it-does)), and reads the newer covers of the branch `live-covers` every day.

Catalog files never say where to get a game: the schemas have no field for it, and the publish guard refuses any URL in them. Results come from compatibility reports (see the issue form) and from Cartouche's game measurements, both measured on real devices; nothing is filled in from guesses. Each Thursday, the Game measurements workflow sums up the game sessions of the 28 days before into one result for each iPhone model that at least three iPhones played the game on, marked by its `measured`, and proposes the sheets that changed on the branch `catalog-measurements` ([telemetry/README.md](../telemetry/README.md#game-sheets)). A tester's result stays as it is.
